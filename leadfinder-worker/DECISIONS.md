| 2026-11-06 | D-21 | **Moved into Project Tools.** The standalone FastAPI/HTMX UI and SQLite file are retired. Data lives in Supabase Postgres as `lf_*` tables (same columns; text uuid ids so the SQLite rows carry over; schema in `supabase/migrations/add_lead_finder.sql`, run by hand like every Project Tools migration) with admin-only RLS via `is_admin()`. The UI is the admin-only Lead Finder tab in the Project Tools React app. The Leads query is the `lf_results(p jsonb)` RPC, a SQL port of `web/queries.py` that returns one jsonb value (no API row cap); `migrate-to-supabase --verify-only` checks it against the Python query. This package became a worker on Fly (`instrata-leadfinder`, one always-on machine, volume at `/data`): the tab queues `lf_job` rows (run, sam_docs, ingest_upload, rescan, triage, triage_resume, office_save, office_active, rescore, bc_disconnect); the worker claims them with `FOR UPDATE SKIP LOCKED`, runs up to 3 at once and writes progress and results back (realtime). Pursue on a SAM lead queues `sam_docs` from a database trigger. Lead folders stay on the worker's volume, so the documents and triage code is unchanged; they are recorded in `lf_document` / `lf_lead_docs` / `lf_triage_run`. The files are not in Supabase Storage (the free plan caps files at 50 MB and storage at 1 GB, and bid zips run to 200 MB): the tab uploads to the worker (`POST /documents/<lead>/upload`, into `/data/inbox/`, then an `ingest_upload` job) and opens files through 5-minute HMAC-signed links (`POST /documents/<lead>/link`). The volume is the only copy (Fly daily snapshots). BuildingConnected tokens and triage agent ids moved from JSON files to `lf_secret` (RLS on, no policies); a token-free status is mirrored to `lf_setting.bc_status`. The OAuth start is `POST /bc/authorize` on the worker, which checks the caller's Supabase token with the Auth server (anon key) and `profiles.role = 'admin'`, as do the document endpoints; the callback returns to the tab. Daily run at 06:00 Eastern by the worker. Python kept, not rewritten in TypeScript, to reuse the tested pipeline. Alembic dropped. | Seth asked for Lead Finder as an admin-only Project Tools tab in its design system, with the data on Supabase. |
| 2026-11-03 | D-20 | **Triage on Claude Managed Agents, not a Messages API loop.** The av-triage skill (unchanged, uploaded from `Skills/av-triage.skill` via the Skills API) reads whole folders with bash, PDF reading and Python, which is what a Managed Agents session provides: a per-session sandbox with the documents mounted read-only, the skill attached to a persisted, versioned agent (`claude-opus-5-5`), output files fetched afterwards. Each session has a hard list-price budget (`TRIAGE_BUDGET_USD`, default $10). Sessions are polled via the events list rather than SSE, so a run left by a restart can be resumed from its recorded session id. Uploaded inputs are deleted from the Files API after each run; sessions are left in place for the Console trace. Manual trigger (button / CLI), not automatic on Pursue, until per-package cost is known. NDA-flagged Bid Board invites need explicit confirmation.
