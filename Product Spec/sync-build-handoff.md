## 7. Lessons learned (avoid re-discovering)

- **monday API:** `Column.settings_str` is gone, use `settings`. Dropdown label edits (`update_dropdown_column`) take the **full** label list, so re-send every existing label with its id (sandbox first, verify after). Date column "Include time" is `settings.show_time_by_default`. `create_update` supports `mentions_list`.
- **Windows PowerShell 5.1:** script files must be **ASCII** (an en-dash becomes a smart quote and breaks parsing). Piping to a native exe **prepends a BOM** even with a no-BOM encoding, so pass arguments instead. Ctrl+V types one character into `Read-Host -AsSecureString`. Don't name variables `$args`. Enable TLS 1.2 for `Invoke-RestMethod`.
- **Claude's shell:** never put backticks or `${}` inside `node -e "…"`. Bash runs them as commands. Edit code with the Edit tool. Validate `.ps1` files with the PowerShell parser before handing them over.
- **Salesforce Flow (Oct 14):** an async path on "created or updated" activates only if every entry condition is **Is Changed**; "only when updated to meet the condition requirements" does **not** fire on create (use a create-only trigger); External Service names are alphanumeric only; a Flow callout treats any HTTP status as success (watch `salesforce webhook rejected` in the engine log). The engine logs a reconcile only when it plans a monday write; check `webhook_inbox` for silent ones.
- **The Salesforce "Developer Console"** now opens the VS Code-style Web Console, which has no query editor.
- **Supabase SQL Editor** shows a false "RLS not enabled" warning on migrations that enable RLS in a `DO` loop.
- **Fly** creates two machines on a first deploy. Use `--ha=false` / `fly scale count 1`.
- **Stale line-item IDs on the board are real:** some "not found" IDs are purged in production too, probably products removed and re-added. They will appear as backfill tasks in production.
- **The sandbox's Salesforce data is a partial sample**, so the sandbox can't confirm whether an ID is missing in production. Check production read-only.
- **monday column ids can be chosen** (Oct 15): `create_column(id: "...")`. Use a fixed id for any column that must survive cross-board moves (`win_loss_notes`, `bid_decision`); a column that exists only on the source board just drops off. Status labels can be created with chosen ids (`defaults: {settings: {labels: [{id, label, color, index}]}}`).
- **`event_log.event_type` has a CHECK list** (created, field_changed, status_changed, stage_changed, writeback, task_*, sync_failure, archived, notified, dry_run_write, group_moved). Fit new events into it (e.g. a failed email = `notified` with `applied = false`) rather than inventing types.
- **Supabase SQL Editor:** an UPDATE reports "Success. No rows returned" even when it changed rows; confirm with a SELECT.
- **Sandbox email:** a refresh appends `.invalid` to every user's email and usually sets Deliverability to system-only, so neither the org's flow email nor the engine's rep email arrives. Check `notified` (applied) in `event_log` instead.
- **The sandbox Pre-Sales board is private (members: Seth + AV Integrations only)**, so the engine can only assign **Seth** as Pre-Sales Engineer there; any other engineer is refused (Oct 19, Erik). Production Pre-Sales is open to the account. Since Oct 19 a refused assignment after R7 no longer loses the work: the Estimator still lands and Hope gets an "Assign <name> on the Pre-Sales Summary" task (`sync_failure:assign_failed:<item>:engineer`, closes when the item has an engineer).
- **Fly API from Seth's network** drops ~1 in 4 connections to `api.machines.dev` (Oct 19): a deploy may need several tries (loop until `fly status` shows the new version); `engine.ps1` calls can time out the same way. Running a read-only admin call from inside the machine (`fly ssh console -C 'node -e ...'` with `process.env.ENGINE_INTERNAL_SECRET`) avoids the network and never exposes the secret.
- **Giving Seth things to copy:** put SQL / commands AFTER the next-step box (or with no box), never only above a box with a question; the box hides the text. A long SQL file can go straight to his clipboard (`Get-Content -Raw file | Set-Clipboard`).
